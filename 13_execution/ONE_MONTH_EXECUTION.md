# One-Month Thesis Execution Plan

## Week 1 — Lock the evidence and topic

Days 1–2:
- verify core dataset access,
- verify exact PCBAS benchmark,
- verify baseline repository,
- verify core papers.

Days 3–4:
- deep-read essential papers,
- build literature matrix,
- identify repeated limitations.

Days 5–6:
- validate candidate research gaps,
- reject unsupported gaps,
- score 5–10 topic variants.

Day 7:
- freeze one research question.

Deliverable:
**Validated thesis problem + dataset + baseline + research gap.**

## Week 2 — Build baseline

- obtain public dataset/features,
- reproduce official baseline if possible,
- build preprocessing pipeline,
- establish evaluation script,
- create experiment tracker,
- establish Git workflow.

Deliverable:
**Working baseline with reproducible metric.**

## Week 3 — Proposed contribution

- implement the smallest defensible contribution,
- run controlled experiments,
- run ablations,
- test robustness,
- compare against baseline,
- document failures.

Deliverable:
**Evidence that the proposed method changes a measurable outcome.**

## Week 4 — System + paper

- build inference API,
- connect dashboard if time permits,
- finalize experiments,
- create figures/tables,
- write thesis,
- write publication draft,
- perform harsh review,
- fix critical weaknesses.

Deliverable:
**Working system + thesis + submission-ready manuscript draft.**

## Scope control
If the AI component becomes too large:
1. freeze heavy visual models,
2. use provided features,
3. reduce architecture complexity,
4. prioritize a defensible experiment,
5. keep backend deployment as the portfolio layer.

## One-month survival rule
A smaller validated contribution is better than an ambitious unfinished model.

## Immediate two-day title checkpoint
Before the one-month execution plan begins in full, there is an urgent candidate-title milestone.

Within two days:
1. falsify the three current candidate families against recent literature,
2. verify dataset and baseline access for the strongest candidates,
3. reject candidates that violate compute, annotation, or zero-cost deployment constraints,
4. prepare 2 to 3 defensible candidate titles for instructor discussion,
5. do not falsely label any candidate as a validated final topic.
